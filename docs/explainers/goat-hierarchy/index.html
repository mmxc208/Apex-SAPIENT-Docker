Goat: hierarchy, echelon, and how step 4b fits the ADRs

A side discussion during step 4b (branch goat-step4b-host-vm), 2026-11-19. The ADRs were read in goatcore at 5c5aee66. Nothing was run for this page. The Markdown version is docs/goat-hierarchy.md.

Five points

  • Mesh peer and fabric identity. A machine joins the mesh; each program on it holds its own slot. Only a pod with a local router needs a bridge.
  • Hierarchy. goat has no cross-site command authority (ADR 0844), so county, city, region and national are relayed level by level by each level's fusion node.
  • ADRs 1165 and 1205 are accepted and are about administration across sites, not about command.
  • Echelon. ADR 0844 would enforce it; ADR 1025, which cuaslab runs, does not. The design that reconciles them is not written.
  • Step 4b meets the slot rules, meets task authority only in part, and misses the mesh rules by design.

What this changes

  • A new open question in docs/goat-roadmap.md, step 4: the echelon gap.
  • No code. No change to cuaslab.
  • The ingress gateway and edge router comparison was already in docs/goat-context.md section 4.1; its tab here is a summary.

With many hosts

The model holds: each new host is one more mesh peer, and each program on it is one more slot. Three things grow:

  • The bridge's allowlist FABRIC_HOST_ANCHORS (emulators/pod_bridge.py): each host anchor that may task the pod is listed.
  • The operator's machine quota on the portal. cuaslab grants 5.
  • A rule for conflicting tasks in the application: two hosts can task one pod, and nothing in goat orders their tasks.

County to national, one level at a time

ADR 0844: "No cross-site command authority in v1". A command echelon at site A cannot publish cmd/effector/B/.... So each level's fusion node relays. Step through a task and a track.

Each level accepts tasks only from the level directly above. In our rig the pod bridge does this with FABRIC_HOST_ANCHORS. No router checks it.

ADR 1165 (Accepted 2026-11-14)

Every site writes. Each site keeps working while cut off (island mode); concurrent writes are kept apart by design.

ADR 1205 (Accepted 2026-11-14)

One site, the hub, outranks the rest. It can override, sever a site, admit a site and create platform admins. Identity edits run at the identity's owner site.

These are about administration across sites, not about command flow. And they give two tiers (the hub and every other site), not four.
